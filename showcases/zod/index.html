Zod

zod.dev →

TypeScript-first schema validation with static type inference. Describe the shape of your data once, then parse and validate untrusted input at runtime.

Utilities
Why it's interesting: TypeScript types vanish at runtime, so they can't protect you from a malformed API response, a bad form submission, or a corrupted JSON blob. Zod closes that gap: you write a schema once and get both a runtime validator and a static TypeScript type inferred from it. safeParse returns a tidy success/error result with precise, path-aware messages — no exceptions to wrangle — which makes it ideal for forms, API boundaries, and config parsing.

Live Form Validation

Every keystroke runs the input through a Zod schema with safeParse. Fields turn red with a precise message, or green when they pass. The success card shows the parsed object — note age arrives as a real number thanks to coercion.

View Code 
import { z } from "zod";

const signupSchema = z.object({
  username: z.string()
    .min(3, "At least 3 characters")
    .max(20, "20 characters max")
    .regex(/^[a-zA-Z0-9_]+$/, "Letters, numbers, underscore only"),
  email: z.email("Enter a valid email"),
  age: z.coerce.number()        // strings → numbers
    .int("Must be a whole number")
    .min(13, "Must be 13 or older")
    .max(120, "That can't be right"),
  website: z.url("Must be a valid URL").optional()
});

// safeParse never throws — it returns a result you can branch on
const result = signupSchema.safeParse(formData);
if (result.success) {
  console.log(result.data);   // fully typed & coerced
} else {
  for (const issue of result.error.issues) {
    console.log(issue.path, issue.message);
  }
}

Nested JSON Validator

Edit the JSON and watch Zod validate a nested schema in real time. Issues report a dotted path straight to the offending field — even deep inside arrays. The schema also has a .refine() that cross-checks total against the line items.

View Code 
const orderSchema = z.object({
  orderId: z.string().startsWith("ORD-", "Must start with ORD-"),
  customer: z.object({
    name: z.string().min(1, "Name is required"),
    email: z.email()
  }),
  items: z.array(z.object({
    sku: z.string(),
    qty: z.number().int().positive("Qty must be positive"),
    price: z.number().nonnegative()
  })).min(1, "Order needs at least one item"),
  total: z.number().nonnegative()
})
// Custom rule across multiple fields, attached to a specific path
.refine(
  (o) => o.total === o.items.reduce((s, i) => s + i.qty * i.price, 0),
  { message: "total must equal the sum of items", path: ["total"] }
);

const result = orderSchema.safeParse(JSON.parse(text));
// result.error.issues[n].path → ["items", 0, "qty"]  ⇒  "items.0.qty"
