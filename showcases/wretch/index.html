Wretch

github.com/elbywan/wretch →

A tiny wrapper around fetch with a fluent, chainable API. Build requests by chaining, and handle responses by status code with named helpers.

Networking
Why it's interesting: Wretch reads like a sentence. You chain configuration — URL, headers, query, body — then chain outcome handlers: .json() for success, and named helpers like .notFound(), .unauthorized(), or .internalError() for specific failure codes. Each one only fires for its status, so error handling stops being a pile of if (res.status === …) checks. It's immutable and composable, so you can build a configured base client and branch off it.
🌐 Demo 1 makes a real request to a public test API (jsonplaceholder.typicode.com) and needs an internet connection. Demo 2 runs fully offline with a simulated server.

Fluent Requests

Configure with one chain, resolve with another. A base client holds the host; .get(path).json() finishes it off and returns parsed data.

Click the button to fetch.
View Code 
// Build a reusable base client, then branch off it
const api = wretch("https://jsonplaceholder.typicode.com");

const id = Math.ceil(Math.random() * 200);
const todo = await api
  .get(`/todos/${id}`)
  .json();   // success resolver

console.log(todo.title, todo.completed);

Handle Responses by Status

Pick a status code and a simulated server returns it. Wretch routes each code to its matching helper — only the relevant one fires. No real network involved.

View Code 
wretch("https://demo.test/resource")
  .get()
  .badRequest(err   => log("400 handled"))
  .unauthorized(err => log("401 handled"))
  .forbidden(err    => log("403 handled"))
  .notFound(err     => log("404 handled"))
  .internalError(err => log("500 handled"))
  .json(data        => log("200 → " + JSON.stringify(data)))
  .catch(err        => log("unhandled: " + err.message));
