ky

github.com/sindresorhus/ky →

A tiny, elegant HTTP client built on the Fetch API. Cleaner syntax, JSON by default, timeouts, and automatic retries — in about 4 KB.

Networking
Why it's interesting: fetch is built into every browser, but it's verbose: you check response.ok yourself, call .json() manually, and there's no retry or timeout. ky wraps fetch with sensible defaults — non-2xx responses throw, .json() is a one-liner, requests retry on transient failures with exponential backoff, and hooks let you tap into the request lifecycle. Same platform primitive, far less boilerplate.
🌐 Demo 1 makes a real request to a public test API (jsonplaceholder.typicode.com) and needs an internet connection. Demo 2 runs fully offline with a simulated server.

JSON in One Line

No response.ok checks, no manual .json() dance. ky.get(url).json() resolves straight to parsed data — or throws if the server returns an error status.

Click the button to fetch.
View Code 
import ky from "ky";

const id = Math.ceil(Math.random() * 10);
const user = await ky
  .get(`https://jsonplaceholder.typicode.com/users/${id}`)
  .json();   // parsed JSON, or throws HTTPError on non-2xx

console.log(user.name, user.email);

Automatic Retries

Here a simulated server returns 503 twice before succeeding. ky retries transient failures automatically with backoff — the beforeRetry hook lets us watch it happen. No real network involved.

// A fake fetch that fails twice, then succeeds
let attempt = 0;
const flakyFetch = async () => {
  attempt++;
  if (attempt < 3) return new Response("nope", { status: 503 });
  return Response.json({ recovered: true, onAttempt: attempt });
};

const data = await ky.get("https://example.invalid/data", {
  fetch: flakyFetch,
  retry: { limit: 3, statusCodes: [503], delay: () => 350 },
  hooks: {
    beforeRetry: [({ retryCount }) => log(`retry #${retryCount} after 503…`)]
  }
}).json();
